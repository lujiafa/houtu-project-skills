## Diff from v3.5.1

v3.5.2 is a stability and bug-fix release; third-party dependency versions remain unchanged.

### Bug Fixes (14 items)

**Critical (9 items):**
- `SimpleSession`: `addRole()`/`getRoles()` incorrectly operated on permissions instead of roles
- `JWTSessionRepository`: missing break in switch caused RSA/ECDSA keys to be overwritten
- `RedisSessionRepository`: String vs Boolean comparison always returned false
- `NacosServiceContext`: null check used `&&` instead of `||`, causing NPE
- `JedisConnectionFactoryBeanUtils`: incorrectly read Lettuce config instead of Jedis config
- `JsonUtils`: constructor self-assigned objectMapper, ignoring injected instance
- `ValidationHandlerExceptionResolverCustomizer`: semicolon condition inverted
- `SecurityWatchAspect`: `m.put()` wrote to wrong map, causing data loss
- `RedisLockAspect`: `tryLock()` return value was ignored

**High (2 items):**
- `FeignDelegateDecoder`: `type.getClass()` checked the Type object instead of the actual return type
- `HttpClients`: removed System.out.println debug statement

**Low (3 items):** spelling fixes ('nust' → 'must', 'paramater' → 'parameter'), removed duplicate `.withCharset()` call

### Feature Enhancements

- **@Lock SpEL support**: the `key` parameter now supports a `#`-prefixed SpEL expression mode with nested property access (e.g., `key = "#user.id"`)
- **RedisLockAspect performance optimization**: parameter name indexes and SpEL Expression parse results are now cached using ConcurrentHashMap

### Removals

- Removed `@ReqMonitor` and `@RpcMonitor` annotations (no corresponding Aspect implementation; non-functional dead code)

### Other

- `DATA_ALREADY_EXIST` error code corrected to 42 (in v3.5.1 it shared the value 41 with `DATA_NOT_EXIST`)
- Completed Jakarta migration: `javax.mail` → `jakarta.mail` (angus-mail)

## Module API Differences

The following differences supplement the generic module-*.md documentation; when this version is loaded, these take precedence.

### houtu-cache (@Lock)

The `@Lock` key in v3.5.2 supports three modes:
- Empty string → `className.methodName`
- Without `#` → exact parameter name match (e.g., `key = "orderId"`)
- `#` prefix → **SpEL expression** (added in v3.5.2), supports nested property access

```java
// SpEL: resolve lock key from nested properties of method parameters
@Lock(prefix = "user:", key = "#user.id")
public void updateUser(User user) { ... }

@Lock(prefix = "vip:", key = "#order.customer.vipId")
public void processVipOrder(Order order) { ... }
```

When the SpEL expression result is null, an AssertionError is thrown. Non-CharSequence types are serialized to the lock key via `JsonUtils.toString()`.
