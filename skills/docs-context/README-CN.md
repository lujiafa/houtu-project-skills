# docs-context

[English](README.md) | 中文

Agent Coding 的**超级基础上下文（Super Base Context）**— 项目上下文加载器与文档同步器，实现上下文修正、补全和重建。

---

## 核心能力

docs-context 通过三大能力解决 Agent Coding 中项目上下文缺失和失真的根本问题。文档是**主干**，承载权威项目知识；但文档不可能涵盖所有内容（尤其在大型微服务 + 前端项目中），因此采用**文档 + 代码扫描 + 注释扫描**协同工作：

| 能力 | 解决什么 | 如何实现 |
|------|---------|---------|
| **修正** | 上下文因长对话衰减、压缩不准确或累积漂移而失真 | 重新读取相关文档并扫描实际代码，恢复准确认知。文档是将失真上下文拉回正轨的事实基准；文档冲突时按优先级链裁决（coding > architecture > tech-stack > modules > decisions） |
| **补全** | Agent 缺乏当前任务所需的项目上下文 | 10 种任务类型智能匹配，按需加载对应文档提供结构性知识（架构、模块边界、依赖、约束）；代码和注释扫描补充文档未覆盖的实现细节 |
| **重建** | 新开会话或首次打开项目，Agent 对项目完全陌生 | 触发 skill 后加载文档（主干）并结合代码和注释扫描，从零重建对项目的完整认知。文档缺失时通过模板初始化创建主干 |

## 解决什么问题

| 问题 | 表现 | docs-context 的应对 |
|------|------|-------------------|
| **项目持续演进下的上下文理解问题** | AI 不了解项目现状，生成的代码与项目风格、约束不一致 | 读模式编码前按任务类型加载对应文档，建立上下文认知。加载后强制确认编码规范合规性，违反约束时主动提醒 |
| **架构随迭代演进逐渐失控** | 架构决策散落在代码和口头沟通中，无人维护全局视图 | architecture.md 持续维护架构全局视图（拓扑、流程、约束），decisions.md 以完整 ADR 格式（背景→方案→决策→后果）记录每次决策演进 |
| **跨会话/多人协作的上下文同步问题** | 换人、换会话后上下文归零，重复沟通成本高 | 5 份持久化文档作为跨工具、跨会话、跨团队的共享知识库，每次会话按任务类型按需加载，上下文即时恢复 |
| **修改类需求的影响范围不可见** | 改一个模块不知道会影响哪些上下游 | modules.md 提供模块依赖拓扑和影响速查表（主干），结合代码扫描确认实际影响范围，写模式同步更新受影响模块描述 |
| **历史设计与决策不可追溯** | "当初为什么这样设计"无人能答 | decisions.md 以 ADR 格式记录决策背景、备选方案对比、最终选择和后果影响。技术选型和架构讨论时自动加载历史决策 |
| **不同粒度的上下文混杂** | 架构级、模块级、代码级信息混在一起，找不到重点 | 5 份文档按职责分离（架构/技术栈/编码规范/模块/决策），文档优先级链明确裁决冲突，任务感知加载只提供当前粒度所需的文档 |
| **文档、注释和代码不同步** | 文档写了不更新，逐渐变成误导 | 写模式编码后按 25 项检查清单逐项核对代码变更，同步更新受影响文档。跨文档一致性检查确保多份文档之间不产生矛盾 |
| **长上下文衰减问题** | 一次性灌入过多上下文，AI 对关键信息的关注度下降 | 当上下文因衰减或压缩而失真时，重新读取文档（主干）并扫描代码和注释修正回来。10 种任务类型选择性加载，只加载当前任务需要的文档 |

## 工作原理

```
编码前（读模式）                    编码后（写模式）
┌─────────────────┐              ┌─────────────────┐
│ 判断任务类型      │              │ 回顾代码变更范围   │
│       ↓         │              │       ↓         │
│ 加载对应文档      │   →  编码  →  │ 逐项检查同步清单   │
│       ↓         │              │       ↓         │
│ 建立上下文约束    │              │ 更新受影响的文档   │
│       ↓         │              │       ↓         │
│ 确认合规·提醒冲突 │              │ 跨文档一致性检查   │
└─────────────────┘              └─────────────────┘
```

## 文档体系

| 文档 | 路径 | 职责 |
|------|------|------|
| 架构文档 | `docs/architecture.md` | 目录结构、项目背景、系统架构、未来规划 |
| 技术栈文档 | `docs/tech-stack.md` | 框架版本、依赖约束、AI 代码生成限制 |
| 编码规范 | `docs/coding.md` | 编码规范、命名约定、API 设计规范、错误处理、日志规范、测试规范 |
| 模块注册表 | `docs/modules.md` | 模块职责、边界、API、依赖关系、影响范围、定时任务、状态枚举 |
| 决策记录 | `docs/decisions.md` | 架构决策记录（ADR：背景→方案→决策→后果） |

所有文档均提供初始化模板，首次使用时按模板创建。模板包含项目类型条件注释，可按需裁剪。
