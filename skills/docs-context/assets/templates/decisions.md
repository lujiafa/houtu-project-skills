# 架构决策记录（Architecture Decision Records）
> 本文件记录项目中的关键架构与技术决策。
> AI 在技术选型、架构讨论时加载本文件了解历史决策，避免重复推翻。
> 维护规则：做出重要决策时追加记录，推翻决策时标记"已替代"并新增替代 ADR。

## 什么时候写 ADR
<!-- 帮助团队判断是否需要记录 -->

以下情况应新增 ADR：
- 在多个技术方案中做出了选择（如选数据库、选框架、选通信方式）
- 制定了影响多个模块的设计规则（如分库分表策略、统一错误码方案）
- 推翻或修改了之前的决策
- 引入了重要的新依赖或中间件
- 对性能、安全、可用性做出了影响架构的权衡

以下情况不需要 ADR：
- 纯代码风格偏好（记录在 `coding.md`）
- Bug 修复
- 不影响架构的功能实现细节
